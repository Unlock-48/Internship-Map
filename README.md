# Chiang Mai Internship Map

เว็บแอปพลิเคชันสำหรับค้นหาและจัดการสถานที่ฝึกงานในจังหวัดเชียงใหม่ พัฒนาขึ้นเพื่อใช้เป็นโปรเจกต์ศึกษาเกี่ยวกับการสร้างเว็บแอปแบบ Full-stack ที่เชื่อมต่อฐานข้อมูลจริง มีระบบแผนที่ การค้นหา การนำเข้าข้อมูล และระบบผู้ดูแลระบบ

## วัตถุประสงค์ของโครงการ

- ศึกษาการพัฒนาเว็บด้วย Next.js และ TypeScript
- ศึกษาการออกแบบ API และการเชื่อมต่อฐานข้อมูล PostgreSQL
- ศึกษาการใช้ Supabase Authentication, Storage และ Row Level Security
- ศึกษาการจัดเก็บและแสดงพิกัดด้วย PostGIS
- สร้างศูนย์กลางข้อมูลสถานที่ฝึกงานสำหรับนักศึกษา
- รองรับการมีส่วนร่วมจากผู้ใช้ผ่านการเสนอข้อมูลและแจ้งข้อมูลผิด

## ฟีเจอร์หลัก

### ผู้ใช้งานทั่วไป

- ค้นหาบริษัท ตำแหน่งงาน และพื้นที่
- กรองตามประเภทหน่วยงาน
- กรองตามลักษณะงาน
- กรองรายการที่ข้อมูลสถานที่ยังไม่ครบ
- แสดงบริษัทบนแผนที่ OpenStreetMap
- แสดงหมุดตามประเภทหน่วยงาน
  - ไม่ระบุ: สีเทา
  - ภาคเอกชน: สีฟ้า
  - ภาครัฐ: สีเหลือง
  - Software House: สีแดง
- คลิกการ์ดบริษัทเพื่อเลื่อนไปยังหมุดบนแผนที่
- ดูรายละเอียดบริษัทและตำแหน่งฝึกงาน
- แสดงรายละเอียดบริษัทควบคู่กับแผนที่ และซูมไปยังรายการที่เลือก
- ส่งข้อมูลฝึกงานใหม่
- แจ้งข้อมูลผิดหรือข้อมูลหมดอายุ

### ผู้ดูแลระบบ

- Login ด้วย Supabase Auth
- เพิ่ม แก้ไข และลบบริษัท
- จัดการข้อมูลตำแหน่งฝึกงานแยกตามประกาศ
- แก้ไขข้อมูลจากหน้า Admin หรือหน้ารายละเอียดงาน
- แก้ไขข้อมูลบริษัท ผู้ประสานงาน ผู้มีอำนาจลงนาม และคำแนะนำอาจารย์
- จัดการมหาวิทยาลัย คณะ ภาควิชา และสาขา รวมถึงกำหนดประกาศที่เปิดรับนักศึกษาจากทุกมหาวิทยาลัย
- แก้ไข Latitude, Longitude ที่อยู่ และลิงก์ Google Maps
- ดึงพิกัดและข้อมูลที่อยู่จากลิงก์ Google Maps พร้อมตรวจสอบก่อนบันทึก
- ประมวลผลเติมข้อมูลตำแหน่งย้อนหลังจากลิงก์ Google Maps โดยเติมเฉพาะช่องว่าง
- ระบุสถานที่ฝึกงานว่าไม่ทราบได้ เมื่อค้นหาไม่พบใน Google Maps
- กรองประกาศที่ไม่ทราบสถานที่ ไม่ทราบจังหวัด หรือยังไม่มีลิงก์แผนที่
- จัดหมวดลักษณะงานของประกาศที่เปิดรับอัตโนมัติจากชื่อตำแหน่งและรายละเอียด โดยไม่ใช้ AI API key
- เติมชื่อตำแหน่งจากรายละเอียดเฉพาะเมื่อมีข้อความระบุไว้อย่างชัดเจน
- นำเข้าข้อมูลจาก Excel
- Preview และตรวจสอบข้อมูล Excel ก่อนยืนยันนำเข้า
- แยกบริษัทและตำแหน่งเดิมออกจากรายการใหม่ด้วยชื่อบริษัท ตำแหน่ง และรายละเอียดงาน พร้อมดาวน์โหลดเฉพาะรายการใหม่
- ตรวจสอบข้อมูลซ้ำกับฐานข้อมูลทั้งใน Preview และก่อนบันทึก
- กรอง แก้ไข และดาวน์โหลดเฉพาะแถวที่ยังมีข้อมูลไม่ครบเป็นไฟล์ Excel
- เติมพิกัดจากที่อยู่หรือลิงก์ Google Maps ในหน้า Preview พร้อมแก้ลิงก์และพิกัดเองได้
- อัปเดตข้อมูลเดิมโดยเติมข้อมูลที่ขาด โดยไม่เขียนทับค่าที่มีอยู่
- ค้นหาและกรองตำแหน่งงานตามมหาวิทยาลัย หน่วยงาน หมวดงาน จังหวัด และสถานะข้อมูลสถานที่
- ใช้เครื่องมือจัดการข้อมูลแบบยุบ/ขยาย เพื่อเพิ่มพื้นที่ให้รายการตำแหน่งงาน
- จัดการประเภทหน่วยงานและประเภทกิจการ
- อัปโหลดโลโก้เว็บไซต์
- ดูและจัดการรายงาน/ข้อเสนอแนะจากผู้ใช้งาน
- ตรวจสอบกล่องจดหมาย
  - เสนอข้อมูล
  - แจ้งข้อมูลผิด
  - กรองประเภทข้อความ
  - เปิดดูรายละเอียดแบบขยาย/ย่อ
  - ทำเครื่องหมายเสร็จแล้ว
  - ทำเครื่องหมายข้อมูลผิด

## การติดตั้งสำหรับการศึกษา

### ติดตั้ง Dependencies

```bash
npm install
```

### ตั้งค่า Environment Variables

คัดลอกไฟล์ตัวอย่าง:

```powershell
copy .env.example .env.local
```

แก้ไข `.env.local`:

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
ADMIN_EMAIL=
```

คำอธิบาย:

- `NEXT_PUBLIC_SUPABASE_URL`: URL ของ Supabase Project
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`: คีย์สำหรับฝั่ง Client
- `SUPABASE_SERVICE_ROLE_KEY`: คีย์สำหรับ Server เท่านั้น
- `ADMIN_EMAIL`: อีเมลที่ได้รับสิทธิ์ Admin

ห้ามเผยแพร่ `.env.local` หรือ `SUPABASE_SERVICE_ROLE_KEY` ลง GitHub

### รันฐานข้อมูล

เปิด Supabase Dashboard > SQL Editor แล้วรัน Migration ตามลำดับ:

```text
001_initial_schema.sql
002_company_detail_fields.sql
003_organization_type.sql
004_short_job_categories.sql
005_short_software_category.sql
006_site_settings.sql
007_category_options.sql
008_import_existing_business_categories.sql
009_multi_university_foundation.sql
```

ไฟล์ `008_import_existing_business_categories.sql` จะดึงประเภทกิจการเดิมจากตาราง `companies` มาเติมในระบบหมวดหมู่

สำหรับฐานข้อมูลใหม่ ให้รัน migration ที่เพิ่มโครงสร้างตามลำดับจนถึง `009_multi_university_foundation.sql` ส่วนฐานข้อมูลเดิมให้ตรวจสอบสถานะ schema ก่อนเลือก migration ที่ยังไม่ได้รัน และสำรองข้อมูลก่อนเปลี่ยนแปลงทุกครั้ง

> **คำเตือน:** `010_reset_application_data_and_rebuild.sql` และ `011_reset_data_for_cmru_excel_template.sql` เป็นสคริปต์รีเซ็ตข้อมูลที่อาจลบข้อมูลเดิม ห้ามรันเป็นขั้นตอนติดตั้งหรืออัปเดตปกติ หากจำเป็นต้องใช้ ให้ตรวจสอบ SQL และสำรองฐานข้อมูลก่อน

## การ Deploy ด้วย Vercel

1. Push โปรเจกต์ไป GitHub
2. เปิด Vercel และเลือก Import Repository
3. เลือก Framework เป็น Next.js
4. เพิ่ม Environment Variables ชุดเดียวกับ `.env.local`
5. Deploy

ต้องเพิ่ม Environment Variables ใน Environment ของ Vercel ให้ครบทั้ง Preview และ Production ตามที่ต้องการ

## ความปลอดภัย

- ไม่เก็บ Secret Key ใน Client
- `.env.local` ถูกกันออกจาก Git ด้วย `.gitignore`
- API ฝั่ง Admin ตรวจสอบสิทธิ์ซ้ำที่ Server
- การแก้ไขข้อมูลบริษัทต้องผ่าน Admin Authentication
- ใช้ Supabase RLS สำหรับตารางสาธารณะ
- Public สามารถสร้างรายงานและเสนอข้อมูลได้ แต่ไม่สามารถอ่านหรือแก้ไขข้อมูล Admin
- Service Role Key ใช้เฉพาะใน Server-side API Routes

## แนวคิดการจัดเก็บข้อมูล

ตารางสำคัญ:

- `companies`: ข้อมูลบริษัท สถานที่ พิกัด และผู้ประสานงาน
- `internships`: ตำแหน่งฝึกงานและรายละเอียดงาน
- `reports`: รายงานข้อมูลผิดจากผู้ใช้งาน
- `submissions`: ข้อมูลฝึกงานที่ผู้ใช้เสนอ
- `category_options`: ตัวเลือกประเภทหน่วยงานและประเภทกิจการ
- `audit_logs`: ประวัติการดำเนินการของ Admin
- `site_settings`: การตั้งค่าเว็บไซต์ เช่น โลโก้

พิกัดบริษัทใช้ระบบพิกัด WGS84 (`SRID 4326`) ผ่าน PostGIS ซึ่งเป็นมาตรฐานเดียวกับ GPS และ Google Maps

## การนำเข้า Excel

ระบบรองรับการ Preview และ Commit ข้อมูล Excel ผ่านหน้า Admin:

1. เปิดหน้า Admin > Import
2. อัปโหลดไฟล์ `.xlsx`
3. ตรวจสอบข้อมูลและข้อผิดพลาด
4. กดยืนยันนำเข้า

ระบบพยายามจับคู่ข้อมูลเดิมด้วย:

1. รหัสบริษัทจากไฟล์
2. ชื่อบริษัทและพื้นที่

เมื่อจับคู่กับรายการเดิม ระบบจะเติมข้อมูลในช่องที่ยังว่างเป็นหลัก และไม่เขียนทับข้อมูลเดิมที่มีค่าอยู่แล้ว เพื่อป้องกันข้อมูลที่ผู้ดูแลแก้ไขไว้สูญหาย

## การจัดหมวดงานอัตโนมัติ

หน้า Admin มีเครื่องมือช่วยเติมข้อมูลของประกาศที่เปิดรับ:

- เติมหมวดลักษณะงานเฉพาะรายการที่ยังไม่มีหมวด โดยใช้ชื่อตำแหน่งและรายละเอียดเทียบกับหมวดที่มีอยู่
- หากมีข้อความงานแต่ไม่ตรงกับหมวดเฉพาะ จะเลือกหมวด `อื่น ๆ`; หากไม่มีข้อมูลพอจะปล่อยไว้ให้ตรวจเอง
- เติมชื่อตำแหน่งเฉพาะเมื่อรายละเอียดระบุชื่อไว้อย่างชัดเจน
- ไม่เขียนทับข้อมูลที่มีอยู่ และมีการยืนยันก่อนประมวลผล
- ใช้กฎจับคู่คำสำคัญในแอป ไม่ต้องใช้ AI API key

## ข้อมูลสถานที่

- ระบบใช้พิกัด Latitude/Longitude สำหรับปักหมุดบนแผนที่
- Admin สามารถวางลิงก์ Google Maps เพื่อดึงพิกัดและลองเติมที่อยู่ได้
- การเติมข้อมูลย้อนหลังจะเติมเฉพาะช่องที่ยังว่าง และไม่แก้รายการที่ Admin ทำเครื่องหมายว่าไม่ทราบสถานที่
- หากค้นหาสถานที่ไม่พบ สามารถเลือก “ไม่ทราบข้อมูลสถานที่ฝึกงาน” ในฟอร์ม Admin เพื่อบันทึกสถานะอย่างชัดเจน
- การแปลงพิกัดเป็นที่อยู่ใช้บริการ OpenStreetMap Nominatim ซึ่งมีข้อจำกัดการเรียกใช้งาน จึงประมวลผลแบบเว้นช่วงคำขอ

## ข้อจำกัดของ Supabase Free

สำหรับข้อมูลข้อความบริษัทและฝึกงานระดับประมาณ 1,000 รายการ โดยทั่วไปถือว่าเพียงพอ เพราะใช้พื้นที่น้อยเมื่อเทียบกับฐานข้อมูลที่ให้มา

ควรติดตาม:

- พื้นที่ฐานข้อมูล
- พื้นที่ Storage โดยเฉพาะรูปภาพ
- Bandwidth
- การสำรองข้อมูล
- การพักโปรเจกต์เมื่อไม่มีการใช้งานเป็นเวลานาน

## แนวทางพัฒนาต่อ

แนวทางต่อยอดที่สามารถทำได้ในอนาคต โดยไม่จำเป็นต้องเปลี่ยนระบบทั้งหมดในครั้งเดียว:

### การจัดการและคุณภาพข้อมูล

- เพิ่มตัวอย่างงานและชุดทดสอบสำหรับกฎจัดหมวดงาน พร้อมหน้าตรวจทาน/อนุมัติผลก่อนบันทึกจำนวนมาก
- เพิ่มคิวตรวจสอบข้อมูลที่ยังขาด โดยให้ Admin มอบหมายและติดตามสถานะการเติมข้อมูลได้
- เพิ่มการตรวจหาบริษัท/ประกาศซ้ำและเครื่องมือรวมรายการ พร้อมประวัติการเปลี่ยนแปลงและการกู้คืน
- เพิ่มการตรวจสอบตำแหน่งบนแผนที่ก่อนเผยแพร่ และแหล่งอ้างอิง/วันที่ยืนยันข้อมูล
- พัฒนาการนำเข้าข้อมูลให้รองรับการจับคู่แบบกำหนดกติกาและรายงานผลการเปลี่ยนแปลงอย่างละเอียด

### การใช้งานและการขยายระบบ

- เพิ่มการแบ่งหน้าและการค้นหาแบบ server-side เมื่อจำนวนประกาศหรือรายงานเพิ่มขึ้น
- เพิ่มบทบาทผู้ดูแลหลายระดับ พร้อมกำหนดสิทธิ์แยกตามการกระทำ
- เพิ่มการส่งออกข้อมูลและรายงานสรุปตามมหาวิทยาลัย หมวดงาน และพื้นที่
- เพิ่มระบบแจ้งเตือนเมื่อมีการเสนอข้อมูลหรือแจ้งข้อมูลผิด
- รองรับพื้นที่และจังหวัดเพิ่มเติม พร้อมการจัดการข้อมูลแผนที่ที่ไม่ผูกกับพิกัด
- พิจารณาเชื่อม AI เพื่อเสนอคำแนะนำหมวดงานได้ภายหลัง โดยให้ผู้ดูแลตรวจและยืนยันก่อนบันทึก และเก็บ API key ฝั่ง Server เท่านั้น

### ความเสถียรและการดูแลระบบ

- เพิ่ม Automated Tests ครอบคลุมการนำเข้า การจัดหมวด การค้นหา และการแก้ไขข้อมูล
- เพิ่ม CI สำหรับ TypeScript, lint, tests และ build ก่อน merge/deploy
- เพิ่ม Monitoring, Error reporting, audit log ที่ละเอียดขึ้น และแนวทางสำรอง/กู้คืนข้อมูล
- ปรับปรุงประสิทธิภาพแผนที่ รูปภาพ และ API ตามการใช้งานจริง

## ลิขสิทธิ์และการใช้งาน

โปรเจกต์นี้จัดทำขึ้นเพื่อการศึกษาและพัฒนาระบบต้นแบบ ผู้พัฒนาควรตรวจสอบใบอนุญาตและข้อกำหนดการใช้งานของบริการภายนอก เช่น Supabase, OpenStreetMap และไลบรารีต่าง ๆ ก่อนนำไปใช้ในเชิงพาณิชย์
